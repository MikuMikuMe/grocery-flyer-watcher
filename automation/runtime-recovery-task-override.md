# Startup recovery addition for the EXISTING watcher

Apply only through an actual task-update operation; preserve the existing private task,
recipients, sources, cadence, enabled state, baselines and quality gate. Do not create a
replacement task. Configuration changes alone do not authorize mail or live deal checks.

Before declaring a blocker, distinguish: current callable action exposure; app approval
settings; provider authentication; runtime availability; genuine private-state access;
and source-verification completeness. Load current schemas, never infer actions from a
plugin's description or a prior model response. After one inconclusive filtered lookup,
use one unfiltered relevant-app listing. Do not keep repeating the same unsuccessful lookup.

Use the pinned, verified `automation/runtime_bootstrap.py` path from docs/RUNTIME_RECOVERY.md
to restore missing local modules and run the production CLI without pip/network or an
installed executable. Fetch missing bytes and Git object metadata through the connected
GitHub reader when direct network fails. A restored executable is not a successful flyer
review. Retry the original quality operation after repair; never weaken its conditions.

Use current action observations with runtime_preflight.py. Exposed actions are not proof
of successful delivery, and Allow all actions is not evidence that the schemas are present.
Do not say the account needs reconnecting without an actual authentication/authorization
error. Do not claim a new operation became available unless its callable schema is loaded.

Restore the real journal from its already-configured durable private store. Do not create
an empty replacement, infer history from missing Sent messages, or treat temporary disk as
proven durable storage. Keep private recipient/offer/delivery state out of public files.
Where a backend genuinely has not been configured, identify that specific missing setup.

Resume each unfinished qualifying event only through the deployed quality build/publication/
preflight/recipient-Sent/authorize/send/ack sequence. Do not switch accounts or mail transports,
retry an uncertain delivery, or invent a new event to work around an earlier failure.
Continue useful independent checks for all other profiles. No automatic tests or status mail.

Changes are live only after the actual repository publication and task-update results are
verified. A missing write/send schema is not fixed by the existence of a public patch.
Preserve pending work privately and report only a persistent blocker needing user action,
without falsely calling incomplete source checks unchanged or complete.
