# Repository-first connected runtime

The native scheduled task remains the only scheduler, source investigator, decision maker,
private checkpoint owner and conditional Gmail sender. This repository contains public code,
policy, tests and verified advertising history, not operational journals or recipient state.

## Offline controller

`src/grocery_flyer_watch/runtime_controller.py` is a standalone standard-library CLI. It
validates the existing `flyer-operation-journal-v1` Markdown JSON block, applies revision-checked
state transitions, generates stable operation IDs, returns conservative recovery actions and
appends keyed entries without changing previous bytes. It never calls external services or
authorizes delivery. Connector operations, real evidence and their independent readback remain
the native executor's responsibility; a boolean passed to the controller is not proof of a
provider write. `continuation.py`, `work_ticket.py`, the source/quality commands and
`repository_delivery.py` remain authoritative for their existing contracts.

Use a private materialized copy of the current journal, a private JSON request and a new output
file; upload the generated bytes to the same private Library path only after checking the
current version. Materialize the saved version and verify exact bytes before moving on.

```sh
python src/grocery_flyer_watch/runtime_controller.py inspect operation-journal.md --request inspect.json
python src/grocery_flyer_watch/runtime_controller.py transition operation-journal.md --request event.json --output next.md
python src/grocery_flyer_watch/runtime_controller.py append run-history.md --request entry.json --output next-history.md
python src/grocery_flyer_watch/runtime_controller.py verify saved.md --request next.md
```

Inspect request: `seq` (observed canonical checkpoint sequence), optional `last_run_id` and
`handoff_run_id` (real provider IDs). Transition request: `expected_revision`, `checkpoint_sequence`,
`action` and action-specific fields. `start` uses a unique `run_key` and optional real native ID
and schedule; `pending` uses identity (`retailer`, `edition`, `stage`, `unit`, `source`, `kind`)
with kind `read_only`, `immutable_write`, or `delivery_reconcile`. Put exact market/channel and
scope into the unit identity. `begin` is required before external effects. `result` stores
`disposition` (`advance`, `no_progress`, `uncertain`), real `evidence`, and for advancement actual
`units` or `artifact`. `reconcile` replaces only uncertain results using verified evidence.
`commit` requires independently verified checkpoint and secondary records (both true), with
an advancing sequence only for actual advancement. `finish` requires verified secondary records.
An append request is `{ "key": "stable-event-id", "body": "actual entry text" }`; identical
replays are no-ops, conflicting replays fail closed. All requests and outputs containing private
state stay private. Readback and version checks cannot be atomically combined across connectors;
run a single executor and reconcile conflicts instead of assuming exactly-once effects.

## Code transfer

Existing CI tests the code offline and packages public source on code changes, not on an hourly
schedule. The runtime archive contains only tracked public package files and the bootstrap helper.
Acquire the archive through the GitHub artifact connector when available, materialize privately,
and verify each required file against the actual pinned Git tree before importing/executing it.
Use a private hash-verified cache to avoid repeated manual transfer; a stale ZIP is not a valid
runtime. If the artifact or connector cannot be materialized, report the precise operation/error,
use individually verified cached modules or connector-fetched bytes, and do safe source work.
No new scheduler, source service, automatic mail or private state in CI.

The existing native checkpoint/delivery gates are unchanged. In particular never retry an
uncertain Gmail send because a journal or Sent search appears empty. Check actual recipient-specific
provider evidence and use the production authorizer. CI and journal tests use synthetic data;
passing them is not source progress, public fact publication or verified live delivery.
